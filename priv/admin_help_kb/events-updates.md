# Events — Updates tab

The **Updates** tab is the third tab in the event editor and is the communication hub for a **published** event. Drafts have no attendees, so updates only make sense after publishing.

## Sending an update

- Compose the update in a rich-text editor.
- Before sending, choose the audience:
  - **Email all attendees** — everyone with a ticket/registration for this event; the recipient count is shown before you confirm.
  - **Show on the public event page** — the update is displayed on the event page for everyone (useful for info that helps people still deciding whether to come).
  - Or both at once.
- Sending asks for confirmation. There is **no unsend** — re-read before confirming, and send a short follow-up correction if a mistake slips through.
- Typical updates: changed parking/entrance instructions, "bring swimwear", revised door times, post-event thank-you with the photo link.

## Photo upload link

- Published events get a shareable **photo upload link** where attendees can contribute their photos without needing an account. The photo collection is created automatically when the event is published.
- Copy the link from the Updates tab and share it during/after the event — in an update email, a group chat, or on a sign at the venue.
- Attendees also receive an **automatic photo reminder email** after the event ends (scheduled by a background worker at publish time).

## Communication timeline

- Below the composer, a timeline lists everything sent for the event with timestamps: the publish notification, every update, and photo reminders.
- Check the timeline before sending to avoid repeating yourself and to confirm what attendees have already been told.

## Troubleshooting

- "Updates tab looks limited/empty" → the event is still a draft; publish first.
- "Recipient count is zero" → nobody has registered yet; an email update would reach no one.
- "Attendees lost the photo link" → re-copy it from the Updates tab and share again.
